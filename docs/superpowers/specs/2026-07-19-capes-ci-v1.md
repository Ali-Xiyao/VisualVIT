# CAPES-CI v1 Authoritative Method and Interface Specification

Date: 2026-07-19  
Authority: this file supersedes conflicting token layouts and learned-matcher shortcuts in the two original proposals for the v1 survival implementation.  
Evidence scope: implementation and survival testing only; formal test data remain sealed.

## 1. Method contract

CAPES-CI is one chain:

```text
frozen region encoder
-> RegionBatch
-> NullAwareMatchGraph
-> MatchPlan / RelationCandidates
-> DeterministicGlobalAllocator
-> AllocationPlan
-> fixed 4/28/28/4 TokenBundle
-> RelationProjector
-> exact 64-placeholder frozen-VLM adapter
-> normalized likelihood over five progression labels
```

The main controlled treatment is the persistent endpoint assignment. B4a and B4b must share input tensors, selected support, token types/count/order/mask, model parameters, initialization, optimizer, prompt and step count. They may differ only in real-real endpoint assignment. Birth/death sets are held fixed in B4 and studied in a separate null intervention.

## 2. Fixed constants

```python
GLOBAL_TOKENS = 4
ENTITY_TOKENS = 28
RELATION_TOKENS = 28
RESERVED_TOKENS = 4
TOKEN_BUDGET = 64
```

The older `8+28+28` layout is invalid. A 64-token run that deletes invalid positions rather than filling them with a shared neutral representation is invalid for the matched-control claim.

## 3. Schemas

### 3.1 RegionBatch

Existing required tensors remain backward compatible. The following observation-only metadata are optional:

```python
prior_boxes/current_boxes: [B,R,4] | None
prior_confidence/current_confidence: [B,R] | None
prior_source_ids/current_source_ids: [B,R] | None
time_delta_days: [B] | None
```

`prior_entity_ids/current_entity_ids` are gold audit labels. They may be read only by oracle construction/evaluation and must never enter learned matching, allocation or projection.

### 3.2 MatchPlan

```python
transport: [B,Rp+1,Rc+1]
mode: str
edge_logits: [B,Rp,Rc] | None
prior_null_logits: [B,Rp] | None
current_null_logits: [B,Rc] | None
diagnostics: dict[str, Tensor|float|int|str] | None
```

For valid mass `a,b`, the real block `P` obeys:

```text
P >= 0; P1 <= a; P^T1 <= b
death = a-P1
birth = b-P^T1
```

The augmented transport stores `death` in the final column, `birth` in the final row and exactly zero at dustbin-to-dustbin. `validate()` checks exact mass accounting; `validate_hard()` additionally requires 0/1 values.

### 3.3 RelationCandidates

Candidate universe is fixed as all prior sources followed by all current sources, so `N=Rp+Rc` is assignment independent.

```python
entity_features: [B,N,F]
relation_features: [B,N,F]
valid_mask: [B,N] bool
unary_scores: [B,N]
anatomy_ids: [B,N] long
temporal_ids: [B,N] long  # 0 prior, 1 current
source_ids: [B,N] long
relation_mass: [B,N]
```

For prior source `i`:

```text
r_i = sum_j P_ij phi(p_i,c_j,persistent) + death_i phi(p_i,0,death)
```

For current source `j`:

```text
r_(Rp+j) = birth_j phi(0,c_j,birth)
```

Entity features are unary and assignment independent. Relation features contain the complete soft assignment effect.

### 3.4 AllocationPlan

```python
weights: [B,28,N]
slot_valid: [B,28] bool
slot_mass: [B,28]
source_valid: [B,N] bool
selected_source_ids: [B,28] long  # -1 for empty, -2 for overflow
overflow_mask: [B,N] bool
```

Every valid source has column mass exactly one across slots; invalid sources have zero mass. `N<=28` maps one source per deterministic slot. `N>28` maps the top 27 sources individually and all remaining valid sources to slot 28. Ranking uses only unary confidence, anatomy coverage, temporal side and stable source ID; it never reads assignment or gold entity ID. Entity and relation streams share the exact same plan.

### 3.5 TokenBundle / ProjectedTokenBundle

`TokenBundle` retains `tokens/token_types/valid_mask/assignment` and adds optional per-token `anatomy_ids`, `temporal_ids`, `confidence`, `slot_mass`, `source_ids`. All are `[B,64]` except token types may remain `[64]` for a shared layout.

`ProjectedTokenBundle` contains:

```python
embeddings: [B,64,H_lm]
token_types: [64]
valid_mask: [B,64]
attention_mask: [B,64]  # all ones for physical budget
position_ids: [3,B,64]  # equal 1-D axes unless model-specific adapter proves otherwise
audit: dict
```

Invalid/reserved positions use a learned shared neutral embedding; positions are never removed.

## 4. NullAwareMatchGraph

The learned matcher must not accept `match_count`, oracle cardinality, oracle IDs or test labels.

It emits match utility `u_ij`, death utility `u_i^d` and birth utility `u_j^b`. Relative edge benefit is:

```text
g_ij = u_ij - u_i^d - u_j^b
```

The v1 differentiable relaxation uses a finite-temperature sub-stochastic capacity projection with anatomy/padding masks and fixed iteration count. Its output must be finite, differentiable, permutation equivariant and feasible within registered tolerance. The exact objective and approximation gap are logged.

Inference hardening solves optional bipartite assignment using the same edge/null utilities. It must be globally optimal on enumerated micro-cases, deterministic under ties, and return no match when matching is worse than the two null alternatives. A greedy matcher is only a baseline.

Required diagnostics:

```text
min_mass
max_prior_residual
max_current_residual
dustbin_dustbin
iterations
temperature
objective_soft
objective_hard
```

## 5. Fixed-budget assembly

- Four globals: prior mean, current mean, directional difference, interaction.
- Twenty-eight entity slots: allocation of assignment-independent unary candidates.
- Twenty-eight relation slots: the same AllocationPlan applied to soft relation candidates.
- Four reserved slots: shared neutral tokens plus overflow/global audit metadata; never sample-label carriers.

When a slot contains multiple sources, feature aggregation is mass-normalized while `slot_mass` separately preserves count/mass. Overflow provenance is recorded; no exception or silent truncation is allowed.

## 6. Frozen-VLM adapter

The adapter receives text `input_ids` containing exactly 64 placeholder positions and a projected bundle. It must:

1. obtain ordinary text embeddings from the frozen VLM input embedding table;
2. replace exactly those 64 embeddings, no more and no fewer;
3. pass no `pixel_values`, image grids or raw image tensors on the relation-token path;
4. preserve a physical attention mask of one for all 64 relation positions;
5. use explicit model-compatible text-like M-RoPE/position IDs;
6. score each of `stable,worse,improved,new,resolved` by length-normalized autoregressive log likelihood;
7. freeze the region encoder and the full VLM; only matcher/projector and explicitly registered adapter embeddings may receive gradients.

Any fallback to raw-image generation is a gate failure. Generation and the strict parser remain non-confirmatory diagnostics only.

## 7. Audit invariants

For every B4 pair, persist hashes for:

- all RegionBatch input/metadata fields;
- allocation weights/order/mask;
- token types/order/valid mask and placeholder mask;
- prompt/input IDs/attention/position IDs;
- model parameter initialization and frozen flags;
- optimizer/scheduler/training steps and random seeds;
- B4a/B4b assignments.

Pass requires every item equal except the assignment hash and relation-token values causally downstream of it.

## 8. Survival gates

1. CPU schema/mass/property tests.
2. CPU differentiable transport and globally optimal micro hardening.
3. CPU/GPU allocator determinism, overflow and B4 isomorphism.
4. toy frozen-LM 64-placeholder injection and five-label scoring.
5. Qwen-2B relation-token forward on retained allocation 4161.
6. 8–16-case end-to-end overfit with five labels and no pixel bypass.
7. Qwen-7B or server-available Qwen3-VL single-seed transfer.
8. Real train/dev B4a/B4b/learned pilot; only after this freezes the formal effect size/power.

Failure stops at the first gate. One preregistered rescue is allowed per gate; no blind seed expansion.

## 9. Explicit non-goals for v1

- no full free-text radiology report generation;
- no clinical causal-effect claim;
- no universal optimality claim for 64 tokens;
- no claim that partial OT, dustbins or relational tokens are individually novel;
- no use of test-set oracle information for training, allocation or hyperparameter selection;
- no release, replacement or cancellation of parent Slurm allocation 4161.
